# 宠物预约业务规则检查

## 用途

检查题目 02 的预约、支付、名额、取消、退款和服务履约是否符合原题及已确认的学生决策。该 Skill 只检查业务规则，不代替完整验收，也不替学生决定题面未明确的策略。

## 触发场景

- 新增或修改预约、支付、退款、核销或履约状态。
- 修改时段容量、5 分钟未付款超时或 2 小时取消规则。
- 处理重复通知、并发抢位、取消与核销竞争或退款失败。
- 需要判断日终统计是否把金额和服务结果正确对应。

## 输入

1. 题目 02 原文和版本号。
2. 项目 `AGENTS.md` 及已填写的学生决策表。
3. 相关源码、数据库迁移、测试、模拟支付回调和页面操作路径。
4. 要检查的预约编号、时段编号或测试用例编号（可选）。

## 执行步骤

1. 校验学生决策表中影响本次检查的项已填写；未填写则输出阻塞，不猜测。
2. 画出或读取预约主状态、支付状态、取消状态、履约状态和退款状态，确认没有用单一“是否付款”覆盖多个事实。
3. 检查容量不变量：每时段有效占位不超过 3；待付款超时、取消和并发操作释放名额最多一次。
4. 检查同宠物同一时段去重、已开始时段拒绝预约、支付回调幂等和关闭后迟到支付异常处理。
5. 检查提前 2 小时取消、临近取消审核、审核期间保留名额且禁止核销、取消后退款独立追踪。
6. 检查核销、服务开始、服务完成、未到店和退款失败的状态边界与权限。
7. 检查取消与核销、支付与超时、重复通知等并发场景是否有唯一合法结果和可复测证据。
8. 检查日终统计是否分别呈现已完成、已取消、未到店、已收款、已退款和退款待处理。

## 输出格式

```markdown
# 业务规则检查结果
- 检查版本：
- 题面版本：
- 决策表版本：
- 结论：通过 / 不通过 / 阻塞

## 检查项
| 编号 | 规则 | 结果 | 证据 | 缺陷/决策 |
|---|---|---|---|---|

## 阻塞项

## 修正建议

## 复测范围
```

结果必须区分“实现缺陷”和“学生尚未决定”，不得把推测写成失败原因。

## 失败处理

- 缺少题面、决策表或版本信息：停止检查并输出阻塞项。
- 发现状态、金额或容量不一致：记录最小复现步骤和实际数据，不直接修改生产代码。
- 发现规则冲突：引用冲突的题面或决策编号，交由学生决定。
- 修复后只重跑受影响检查，并保留修复前后结果。

## 完成标准

- 所有适用规则均有通过/不通过/阻塞结论。
- 关键异常路径至少有一次可复测证据。
- 名额、支付、取消、履约和退款记录可追溯。
- 学生决策未被 Skill 擅自补充。
