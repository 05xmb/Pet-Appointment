# DEV01 基础服务实施计划

目标：在 `dev/02` 实现题目 02 的 Go/MySQL 基础、预置账号密码登录、服务端会话和持久化教学时钟；此阶段不实现预约交易，也不发布 HTTP 教学地址。

设计：单体 Go HTTP 服务使用 `database/sql` 与 MySQL 8。认证使用密码慢散列、随机不透明会话令牌，数据库只存令牌摘要；业务角色和归属从服务端账号记录读取。会话有效期使用真实时间，预约边界和日清使用可持久化的教学时钟与 `Asia/Shanghai`。HTTPS 入口尚未确认，正式账号密码登录不得部署到当前明文 HTTP 地址。

取舍：内存会话少一张表，但重启丢失，不符合本项目持久化追溯；数据库会话多一张小表，可测试登出与过期。账号初始密码由部署者在安全的初始化流程中输入，不在源码、仓库或日志中放默认口令。

## 任务 1：认证核心

- 新建 `go.mod`、`internal/auth/service.go` 和 `internal/auth/service_test.go`。
- 先测试：正确密码产生不透明令牌，仓库只收到摘要；错误密码统一拒绝；会话返回服务器记录的身份，过期及登出失效。
- 运行 `go test ./internal/auth -v`，先确认失败原因为缺少行为，最小实现后复测。

## 任务 2：MySQL 适配与初始化

- 新建 `internal/store/mysql`，完成幂等建表、账号/会话存取、教学时钟和预置门店、宠物、项目、未来三个时段。
- 先写数据库集成测试，使用独立测试库 `pet_appointment_test_<hex>`；只对明确的测试库建表和清理，不触碰已有业务数据。
- 需要本机可用的测试数据库连接参数；没有时仅完成可离线验证的部分，并如实记录未验收项。

## 任务 3：HTTP 接口与本地验收

- 新建 `internal/httpapi` 与 `cmd/pet-appointment`；先测试登录、登出、身份查询、跨站状态请求、未登录、伪造身份和安全 Cookie，再实现最小处理器。
- 接口从会话加载角色和归属；不接收请求中的角色/用户编号作为授权依据。会话 Cookie 设 `HttpOnly`、`Secure`、`SameSite`，正式登录只经 TLS 入口开放。
- 运行 `gofmt`、`go vet ./...`、`go test ./...`、`go test -race ./...` 及覆盖率，记录未完成的业务和集成测试。完成代码后由独立测试与验收会话复核，不由开发结果代替。

说明：本计划是施工顺序，不等于已完成；不自动提交、推送、合并或部署。
